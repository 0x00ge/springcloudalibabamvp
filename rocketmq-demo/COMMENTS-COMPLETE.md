```java
/**
 * 幂等性问题 ⚠️
 * 
 * 消息可能重复消费，原因：
 * 1. 消费成功但 ACK 失败（网络抖动）
 * 2. Broker 认为消费超时，重新投递
 * 3. 消费者重启，重新拉取消息
 * 
 * 解决方案：
 * 1. 数据库唯一索引（最简单）
 * 2. Redis 去重（高性能）
 * 3. 业务逻辑天然幂等
 */
```

**重点注释**：
```java
/**
 * 顺序消息的原理
 * 
 * 1. Topic 有多个队列（Queue）
 * 2. 同一个 hashKey 的消息发送到同一个队列
 * 3. 队列内的消息按顺序消费
 * 
 * 举例：
 * - 订单 A 的所有消息（hashKey=订单A）→ Queue 1
 * - 订单 B 的所有消息（hashKey=订单B）→ Queue 2
 * - 订单 A 和 B 之间不保证顺序
 * - 但订单 A 内部的消息严格有序
 */
```
